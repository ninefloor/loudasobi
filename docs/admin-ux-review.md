# 관리자 UI/UX 검토

## 현재 판단

`AdminMusicManager`는 검색 가능한 곡 목록과 설정 폼으로 나뉘어 소수 곡을 관리하기에는 충분합니다. 다만 공개 여부·가사 연결 상태가 보조 문장에 묶여 있고, 설정 저장 버튼은 긴 폼의 하단에 있어 곡 수가 늘거나 반복 편집할 때 불편합니다. shadcn 컴포넌트를 더 활용하되 현재 내부 스크롤 구조는 유지하는 것이 좋습니다.

## 이번 반영

- 추천 정렬 작업을 `/admin/sidebar`로 분리했습니다. 곡 설정과 목록 편집의 저장 범위를 섞지 않습니다.
- shadcn Button, Badge, Input, NativeSelect, ScrollArea로 그룹·드래그·이동 버튼·저장 상태를 구성했습니다.
- 저장 버튼을 고정 헤더에 두고, 오른쪽에 공개 추천순 미리보기를 배치했습니다.
- 드래그를 쓰기 어려운 환경에서는 위/아래 버튼과 그룹 선택으로 동일 작업을 할 수 있습니다.
- 동시 편집 충돌, 공개곡 변경, 저장 실패는 초안을 보존하고 안내합니다. 최신 목록 재조회와 초안 복사를 제공합니다.

## 다음 개선 제안 — 아직 미적용

1. **관리 영역 탐색**: shadcn Tabs 또는 NavigationMenu로 `곡 설정 / 추천 목록` 진입점을 통일합니다. 콜 편집은 선택한 곡의 작업이므로 독립 전체화면을 유지합니다.
2. **상태 필터**: Select/Tabs로 `전체 / 공개 / 비공개`를 구분하고, Badge로 `음원 미입력 / 가사 없음 / BPM 미지정`을 구별합니다. BPM 미지정은 저장 오류가 아닌 참고 상태로 취급합니다.
3. **곡 설정 폼**: Card 또는 Separator로 `음원·BPM / 팬라이트 / 싱크 / 공개`를 분리하고, 고정된 저장 영역에 저장 여부를 표시합니다. 신규 타이틀 CRUD는 추가하지 않습니다.
4. **확인·피드백**: 기본 confirm을 shadcn AlertDialog로, 인라인 오류를 Alert로 통일하면 취소·실패 메시지를 더 명확히 전달할 수 있습니다. 성공 메시지만 Toast로 보완합니다.
5. **작업 이어가기**: 콜 편집에서 돌아오면 이전 선택곡·검색어·스크롤 위치를 복원합니다. 우선 URL 상태로 해결하고 전역 상태 라이브러리 확장은 피합니다.

권장 순서는 상태 필터 → 설정 폼·고정 저장 → 작업 위치 복원입니다. 실제 콜 입력 중 확인된 불편을 우선하며 대시보드·통계·새 디자인 체계는 만들지 않습니다.
